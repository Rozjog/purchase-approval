# Purchase Approval — система согласования закупок

**Purchase Approval** — учебное веб-приложение для учёта заявок на закупку и их согласования. Система позволяет просматривать сотрудников, заявки, согласования и принятые решения, искать и фильтровать записи, а также анализировать статистику закупок.

## Возможности

- Просмотр списков сотрудников, заявок, согласований и решений.
- Просмотр подробной информации об объектах и связанных с ними данных.
- Поиск заявок по названию, контрагенту и имени сотрудника.
- Фильтрация заявок по минимальной сумме и статусу.
- Сортировка заявок по идентификатору, названию, сумме или сотруднику.
- Постраничный вывод заявок с сохранением параметров поиска и фильтров.
- Статистика закупок: количество и общая сумма заявок, распределение по статусам, сумма одобренных заявок, количество заявок по сотрудникам и пять самых дорогих заявок без отменённых.
- Обработка запросов к несуществующим объектам с ответом HTTP 404.

Веб-интерфейс предназначен для **просмотра и анализа данных**. Создание, изменение и удаление объектов доступны через Django Shell; веб-формы для этих операций не реализованы.

## Модели данных

Система включает четыре взаимосвязанные модели Django:

| Модель | Назначение | Основные поля |
|---|---|---|
| `Employee` | Сотрудник | `name`, `role` |
| `Request` | Заявка на закупку | `name`, `amount`, `contractor`, `employee`, `status` |
| `Approval` | Согласование заявки | `request`, `employee`, `status` |
| `Decision` | Решение по согласованию | `approval`, `result`, `comment` |

Связи реализованы через `ForeignKey`:

- Заявка принадлежит сотруднику, который её создал.
- Согласование относится к заявке и ответственному сотруднику.
- Решение относится к согласованию.

Для связанных записей применяется `on_delete=models.PROTECT`, чтобы предотвратить случайное удаление используемых объектов. Для обратного доступа к связанным данным настроены `related_name`.

Предметная логика включает отмену заявки (`Request.cancel()`), проверку полномочий согласующего (`Approval.can_approve()`) и применение результата решения (`Decision.apply()`). Руководитель отдела может согласовывать заявки на сумму до 250 000 рублей включительно, директор — свыше 250 000 рублей.

## Архитектура

Приложение построено на архитектуре Django **MTV (Model–Template–View)**:

1. `urls.py` сопоставляет URL с представлением.
2. `views.py` обрабатывает HTTP-запрос и получает данные через Django ORM.
3. Модели из `models.py` описывают сущности и связи базы данных.
4. Представление передаёт результаты в HTML-шаблон через `render()`.
5. Шаблон формирует страницу для браузера.

Для работы со связанными данными используются `ForeignKey` и `select_related()`. Фильтрация и поиск реализованы через `filter()`, `Q()` и `icontains`, статистика — через `aggregate()`, `annotate()`, `Count()` и `Sum()`, постраничный вывод — через `Paginator`.

## Установка и запуск

Команды ниже рассчитаны на **Windows CMD**. Выполняйте их из корневого каталога проекта.

**1. Создать и активировать виртуальное окружение:**

```cmd
python -m venv venv
venv\Scripts\activate
```

**2. Установить зависимости:**

```cmd
python -m pip install -r requirements.txt
```

**3. Проверить конфигурацию и применить миграции:**

```cmd
python manage.py check
python manage.py migrate
```

**4. Заполнить базу данными (если требуется).** Если доступна исходная база `data/purchase_approval.sqlite`, перенесите записи в базу Django:

```cmd
python db/import_sqlite_to_orm.py
```

Скрипт переносит сотрудников, заявки, согласования и решения с сохранением их идентификаторов и связей. Если исходной базы нет, приложение может работать с пустыми таблицами Django.

**5. Запустить сервер:**

```cmd
python manage.py runserver
```

Открыть в браузере: **http://127.0.0.1:8000/**

Для локальной разработки в `purchase_approval/settings.py` должен быть настроен подходящий режим отладки (`DEBUG=True`); его не следует использовать в публичном развёртывании.

## База данных

Рабочая база приложения — **`db.sqlite3`**, указанная в настройке `DATABASES` файла `purchase_approval/settings.py`. Структурой таблиц управляют миграции Django.

Файл `data/purchase_approval.sqlite` содержит исходные данные, которые можно перенести с помощью `db/import_sqlite_to_orm.py`. Файлы `sql/schema.sql`, `sql/queries.sql` и `db/database.py` сохранены как отдельная реализация доступа к данным, но веб-представления работают через Django ORM.

Посмотреть состояние миграций:

```cmd
python manage.py showmigrations
```

Открыть Django Shell для работы с моделями:

```cmd
python manage.py shell
```

Пример получения заявок со связанными сотрудниками:

```python
from purchase_requests.models import Request

requests = Request.objects.select_related("employee").order_by("id")
for item in requests:
    print(item.name, item.employee.name, item.amount)
```
