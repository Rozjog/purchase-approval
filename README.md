# Purchase Approval – система согласования закупок

## Назначение

Purchase Approval – учебное приложение для создания и согласования заявок на закупку. Консольная версия приложения (ПР3) дополнена веб-интерфейсом на Django (ПР5).

Приложение позволяет:

- просматривать сотрудников и информацию о конкретном сотруднике в браузере;
- просматривать заявки на закупку и информацию о конкретной заявке;
- просматривать согласования и сведения о них;
- просматривать решения по согласованиям;
- создавать сотрудников, заявки, согласования и решения в консольной версии;
- находить и отменять заявки в консольной версии;
- проверять права согласующего сотрудника и учитывать бюджет;
- хранить данные между запусками приложения.

## Используемые технологии

- Python 3 – язык программирования;
- Django 5.2 – веб-фреймворк;
- HTTP – обмен запросами и ответами между браузером и сервером;
- HTML – разметка веб-страниц;
- CSS и Bootstrap 5.3 – оформление веб-интерфейса;

## Целевая аудитория

Сотрудники и руководители организации, которым необходимо оформлять заявки на закупку, проводить согласования и просматривать результаты принятых решений.

## Предметная область

Основными объектами предметной области являются:

- сотрудник;
- заявка;
- согласование;
- решение.

Сотрудник создаёт заявку на закупку. Для заявки формируется согласование, связанное с согласующим сотрудником. Возможность согласования определяется ролью сотрудника и суммой заявки; при положительном решении также учитывается доступный бюджет. Принятое решение изменяет статус согласования и заявки.

## Основные сущности

### Employee – сотрудник

Объект `Employee` представляет сотрудника системы.

Основные атрибуты:

- `id` – уникальный идентификатор сотрудника;
- `name` – имя сотрудника;
- `role` – роль сотрудника.

Основные методы:

- `__str__()` – строковое представление сотрудника.

### Request – заявка

Объект `Request` представляет заявку на закупку.

Основные атрибуты:

- `id` – уникальный идентификатор заявки;
- `name` – название заявки;
- `amount` – сумма закупки;
- `contractor` – контрагент;
- `employee` – объект `Employee`, создавший заявку;
- `status` – статус заявки.

Основные методы:

- `cancel()` – отмена заявки;
- `__str__()` – строковое представление заявки.

### Approval – согласование

Объект `Approval` представляет согласование заявки уполномоченным сотрудником.

Основные атрибуты:

- `id` – уникальный идентификатор согласования;
- `request` – объект `Request`;
- `employee` – объект `Employee`, выполняющий согласование;
- `status` – статус согласования.

Основные методы:

- `can_approve()` – проверка права сотрудника согласовать заявку в зависимости от её суммы и роли сотрудника;
- `__str__()` – строковое представление согласования.

### Decision – решение

Объект `Decision` представляет результат рассмотрения согласования.

Основные атрибуты:

- `id` – уникальный идентификатор решения;
- `approval` – объект `Approval`;
- `result` – результат решения;
- `comment` – комментарий.

Основные методы:

- `apply()` – применение результата к согласованию и заявке;
- `__str__()` – строковое представление решения.

## Страницы веб-интерфейса

- `/` – главная страница: описание проекта и навигация (view-функция `index()`);
- `/employees/` – список сотрудников из `data/employees.json` (`employees()`);
- `/employees/<int:employee_id>/` – страница сотрудника (`employee_detail()`);
- `/requests/` – список заявок из `data/requests.json` (`requests()`);
- `/requests/<int:request_id>/` – страница заявки (`request_detail()`);
- `/approvals/` – список согласований из `data/approvals.json` (`approvals()`);
- `/approvals/<int:approval_id>/` – страница согласования (`approval_detail()`);
- `/decisions/` – список решений из `data/decisions.json` (`decisions()`);
- `/decisions/<int:decision_id>/` – страница решения (`decision_detail()`).

Если объект с указанным идентификатором не найден, соответствующая страница возвращает HTTP-статус `404`.

## Основные операции

### Используется в веб-интерфейсе (ПР5)

- просмотр списка сотрудников и карточки сотрудника;
- просмотр списка заявок и карточки заявки;
- просмотр списка согласований и карточки согласования;
- просмотр списка решений и карточки решения;

### Отложено до следующих работ

Эти операции реализованы в консольной версии ПР3. Веб-интерфейс будет дополнен ими после изучения форм и POST-запросов:

- добавление сотрудников;
- создание заявок;
- поиск и отмена заявок через веб-интерфейс;
- создание согласований;
- принятие решений с проверкой прав и бюджета.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

- `data/employees.json`;
- `data/requests.json`;
- `data/approvals.json`;
- `data/decisions.json`.

При загрузке данные из JSON преобразуются в объекты `Employee`, `Request`, `Approval` и `Decision`. При сохранении объекты преобразуются обратно в данные JSON.

Связи между объектами в JSON представлены идентификаторами: `employee_id` в заявках, `request_id` и `employee_id` в согласованиях, `approval_id` в решениях.

Загрузка выполняется последовательно: сначала сотрудники, затем заявки, согласования и решения. В ПР5 веб-страницы читают данные из тех же JSON-файлов; переход к Django ORM запланирован на последующие практические работы.

## Назначение модулей

### `main.py`

Консольная версия приложения (сохранена с ПР3). Отвечает за запуск меню, ввод данных и выполнение операций с сотрудниками, заявками, согласованиями и решениями.

### `purchase_approval/`

Пакет конфигурации Django-проекта:

- `settings.py` – настройки Django и список подключённых приложений;
- `urls.py` – маршрутизация верхнего уровня;
- `asgi.py`, `wsgi.py` – точки взаимодействия с сервером.

### `homepage/`

Django-приложение главной страницы:

- `views.py` – функция `page()` для общего HTML-каркаса и view-функция `index()`;
- `urls.py` – маршрут `/`.

Функция `page()` подключает Bootstrap 5.3 и формирует навигацию для всех страниц.

### `employees/`

Django-приложение сотрудников:

- `views.py` – `employees()` и `employee_detail()`;
- `urls.py` – маршруты `/employees/` и `/employees/<int:employee_id>/`;
- `models.py` – пока без Django-моделей.

### `purchase_requests/`

Django-приложение заявок:

- `views.py` – `requests()` и `request_detail()`;
- `urls.py` – маршруты `/requests/` и `/requests/<int:request_id>/`;
- `models.py` – пока без Django-моделей.

### `approvals/`

Django-приложение согласований:

- `views.py` – `approvals()` и `approval_detail()`;
- `urls.py` – маршруты `/approvals/` и `/approvals/<int:approval_id>/`;
- `models.py` – пока без Django-моделей.

### `decisions/`

Django-приложение решений:

- `views.py` – `decisions()` и `decision_detail()`;
- `urls.py` – маршруты `/decisions/` и `/decisions/<int:decision_id>/`;
- `models.py` – пока без Django-моделей.

### `models/`

Пакет классов предметной области из ПР3:

- `employees.py` – класс `Employee` и функции работы с сотрудниками;
- `requests.py` – класс `Request` и функции работы с заявками;
- `approvals.py` – класс `Approval` и функции работы с согласованиями;
- `decisions.py` – класс `Decision` и функции работы с решениями.

Не следует путать этот пакет с `models.py` внутри Django-приложений: в ПР5 данные по-прежнему загружаются через `storage.py` из JSON.

### `storage.py`

Отвечает за загрузку и сохранение данных:

- JSON → объекты Python;
- объекты Python → JSON.

### `utils.py`

Содержит вспомогательную функцию консольного ввода `input_int()`.

### `tests/`

Содержит автоматизированные тесты классов и операций из ПР3.

## Запуск приложения

Установить зависимости в виртуальном окружении:

```text
pip install -r requirements.txt
```

При первом запуске Django применить встроенные миграции:

```text
python manage.py migrate
```

Веб-версия (Django):

```text
python manage.py runserver
```

Открыть в браузере:

```text
http://127.0.0.1:8000/
```

Консольная версия (сохранена):

```text
python main.py
```
